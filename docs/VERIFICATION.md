## Библиотека и конфиденциальность

pymobiledevice3 11.55.0, исходный SHA `b08cee88ecd1d7afebc59882563c98addad8bc9e`.
SHA-256 wheel: `b85b9589778679b43472d06ead7052364a6b06d43383b7d4ccbe390fcbafa5a1`.
Основные изученные файлы wheel совпали с исходниками. Реальные IPCC не получались.

autopair=False запрещает новое сопряжение, но проверяет существующее и открывает
сессию. Фабрика читает полный GetValue и перечитывает его после открытия сессии.
Pairing record ищется в usbmuxd, системном Apple Lockdown, затем локальном каталоге.
Переданный каталог меняет только последний источник. Временный каталог применяется
лишь при отсутствии штатного локального каталога.

_forget_pair_record вызывается из unpair и может удалять записи локально/usbmuxd.
Приложение этот путь не вызывает. Ошибка TLS может сбросить запись только в памяти.
Фабрика создаёт соединение до try и ловит Exception. CancelledError до возврата
клиента не гарантирует закрытия внутреннего соединения до выхода процесса;
после отмены команда завершается, ОС закрывает соединение. Полученный клиент
закрывается в finally. Штатный TLS пишет существующий приватный ключ в системный
temp до try. Удаление в finally не гарантирует очистки при ошибке записи или аварии.
Diagnostics не используется: MobileGestalt документирован как недоступный с iOS 17.4.

## Уточнения по аудиту PR #2

CLI перенастраивает stdout/stderr на UTF-8, включая каналы и файлы. На Linux
воспроизведён UnicodeEncodeError при cp1252 до исправления.
Имена исходных файлов не выводятся; check использует порядковые номера.
Все *.plist внутри bundle проверяются на читаемость, без толкования дополнительных данных.
По уточнению владельца на проверенной Windows 11 USB работает через
AppleMobileDeviceProcess без службы Apple Mobile Device Service. Нужны работающие
компоненты Apple (iTunes или Apple Devices), конкретное имя службы не обязательно.

## v0.2: установка на одну линию

База: main `705f314368a1dfd7fb92ffe159f3ec2806067083`.
Прочитаны AGENTS.md, CLAUDE.md, весь src/ и tests/, scripts/build_windows.py,
.github/workflows/ci.yml, README.md, README_EN.md и этот документ на указанном SHA.
Сначала локальный checkout содержал старый каркас; актуальный main проверен через
GitHub и затем получен git fetch. Изменения выполняются в отдельной ветке.

Изучены файлы установленной pymobiledevice3 11.55.0: installation_proxy.py,
diagnostics.py (методы action/restart), afc.py (создание каталогов, запись файлов,
удаление), progress.py, lockdown_service.py, usbmux.py, lockdown.py и exceptions.py
в части вызываемых путей. Весь пакет целиком не аудировался.
Запусков с реальным iPhone и настоящими IPCC не было.

Уточнение контекста: classify_zip_file проверяет первую ZIP-запись с `/`.
Запись `Payload/` первой мешает распознаванию IPCC. Это воспроизведено на синтетическом ZIP.
_upload_ipcc создаёт каталоги только по ZIP-записям каталогов; set_file_contents родителей
не создаёт. prepare теперь первым пишет целевой bundle-каталог, затем все каталоги
в порядке от родителей к потомкам, затем файлы. Это проверено классификатором и
загрузчиком установленной библиотеки с подменённым AFC, который запрещает запись
в отсутствующий каталог. Внутренние файлы и метаданные сравниваются побайтно.
Подготовленные байты и полные идентификаторы остаются в памяти.

install_from_bytes передаёт распакованные файлы через AFC, устанавливает
PackageType=CarrierBundle и ждёт Complete. Приложение ограничивает вызов 120 с.
Complete сам по себе не доказывает применение профиля. Служба прогресса использует
подписи ipcc/install, объёмы и проценты, без путей с идентификаторами. Логи отключены.
AppInstallError не выводится; по InstallProhibited выбирается отдельное сообщение.
Нерекурсивный rm_single(force=True) может оставить файлы на телефоне, его результат
библиотека не проверяет. Очистка приложением не добавлялась.

restart возвращается без результата после ответа Success. Закрытие диагностики
необходимо для начала перезагрузки. После успешного запроса ошибки закрытия диагностики
и lockdown подавляются без подробностей и не препятствуют последующему подтверждению.
Тесты проверяют также этот случай. Источник pairing records выбирается на всю операцию;
временный каталог существует при каждом подключении, включая финальное чтение,
и удаляется после операции при успехе, ошибках и отмене. Штатный каталог сохраняется.

Подтверждение требует Complete, успешного restart, успешного USB-опроса с отсутствием
исходного serial среди USB-устройств, возврата и точного профиля/версии выбранной линии,
сохранения состава по Slot/SIM и остальных линий. Ошибки списка не означают отключение.
Сетевые подключения с тем же serial не считаются USB. Повторяются только опросы и чтение.
Установка/restart вызываются не более одного раза. Отмена во время установки проверена
как CancelledError и настоящим SIGINT в отдельном процессе с подменёнными службами.

Повторное чтение после перезагрузки распознаёт PasscodeRequiredError и
PasswordRequiredError. Иные причины недоступности повторяются до общего срока чтения,
без объявления их запросом кода; другие исключения блокировки отдельно не распознаются.
Признак загрузочной сессии отсутствует: перезагрузка подтверждается только косвенно.
Полнота схемы линий по-прежнему не доказана для других телефонов/iOS.

Синтетические сценарии: успех, тот же пакет, точный/приблизительный/отсутствующий возврат,
отказ подтверждения/TTY/EOF, оба типа отказа установки, тайм-аут, обрыв, отмена,
ошибка restart, ошибки закрытия, незамеченное отключение, ошибки USB-списка,
ожидание кода обоих известных типов, изменение другой линии, состава, пары Slot/SIM,
целевого профиля и его версии, неполные данные, перестановка строк, недоступное чтение.
В сценариях CLI отдельно проверяется отсутствие полных синтетических идентификаторов
в stdout/stderr, исходных путей и serial; счётчики запрещают повторы записи/restart.

Существующие тесты не удалены. test_no_forbidden_imports заменён проверкой импортов
в модулях чтения/подготовки: прежний общий запрет служб противоречит добавлению install.
Существующие проверки отсутствия автосопряжения и offline check сохранены.

Windows onedir получает явные hidden imports installation_proxy, diagnostics и afc.
Runtime hook при ICM_IMPORT_SMOKE=1 импортирует эти службы внутри EXE без их открытия;
offline smoke запускается вне checkout. Обычные команды не запускают этот smoke.
Фактические результаты ruff, pytest, Linux/Windows CI и onedir фиксируются в PR и отчёте.
Локальная ОС этой сессии Linux; onedir локально на Windows не запускался.

Подпись остаётся UNVERIFIED, криптографии в v0.2 нет. Более раннее намерение перенести
её на v0.2 выше является исторической записью и заменено текущим ТЗ.
Не проверены реальные установка, перезагрузка, применение на двух eSIM, возврат,
совместимость с iOS, 5G/VoWiFi, остатки PublicStaging и аварийные сценарии библиотеки.
Особые зоны регрессий: общая подготовка ZIP и выделение открытия lockdown из чтения.
Их прежние тесты сохранены и дополнены; USB на реальном устройстве не проверялся.
